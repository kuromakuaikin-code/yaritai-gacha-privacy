# ai-companion — デスクトップコンパニオン自作計画

BOOTH の「Kawaii Agent V2」相当のものを、自分の手で作ってみるプロジェクト。
脳 (ローカルLLM)・声 (VOICEVOX)・体 (VRM) を「つなぐ係」を書くのが本体。

## ロードマップ

| Phase | 到達点 | 状態 |
|---|---|---|
| 0 | 人格つきの会話がターミナルで返る | ✅ `chat.mjs` |
| 1 | 返事が VOICEVOX の声で再生される | ✅ `chat.mjs` (VOICEVOX 起動時に自動で有効) |
| 2 | 透過ウィンドウに VRM キャラが立つ | ✅ `app/` (Electron + three.js + @pixiv/three-vrm) |
| 3 | 表情が会話に連動する | ✅ `app/` (感情タグ + 表情のクロスフェード) |
| 4 | 口が動く (音量ベースのリップシンク) | ✅ `app/` (WebAudio の AnalyserNode + 擬似口パク) |
| 5 | 音声入力 (Whisper) | 未着手 |
| 6 | 記憶と親密度 (SQLite) | 未着手 |
| 7 | Live2D モデル対応 (体の差し替え式) | 検討中。技術は pixi-live2d-display が有力。販売時は Live2D SDK の許諾要確認 |

## 動かし方 (自分の PC で)

必要なもの:

- Node.js 18 以上
- LM Studio (https://lmstudio.ai) + モデル (Gemma 4 など)
- VOICEVOX (https://voicevox.hiroshiba.jp) … 任意。あると声が出る

手順:

1. LM Studio を起動し、モデルをロード → Developer タブで **Start Server**
2. (声が欲しければ) VOICEVOX を起動しておく
3. このフォルダで:

   ```
   node chat.mjs
   ```

依存パッケージのインストールは不要 (`npm install` なし)。

## デスクトップに立たせる (Phase 2 / `app/`)

ターミナルではなく、デスクトップの上にキャラを立たせる版です。
背景が透過した枠なしウィンドウに VRM が立ち、話しかけると吹き出しと声で返します。

### 動かし方 (Windows / Mac 共通)

```
git pull
cd ai-companion/app
npm install
npm start
```

`npm install` は初回だけ。Electron 本体 (約 100〜200MB) を取りに行くので少し待ちます。
LM Studio と VOICEVOX の準備は `chat.mjs` と同じで、無くても起動はします
(LM Studio が無いときは、吹き出しに起動手順が出ます)。

### VRM モデルの入れ方

**モデルは同梱していません。**「あなたの推しを入れる器」なので、自分で用意した
`.vrm` ファイルを入れてください。

- 初回起動でパネルが出ます。**ファイルをドラッグ＆ドロップ**するか、
  「VRM ファイルを選ぶ」から選びます
- 選んだ場所は記憶され、次回の起動から自動で読み込まれます
- 別のモデルに変えるときは、キャラを**右クリック → 「別の VRM に変える」**
- VRM 0.x / 1.0 のどちらでも読めます

### 操作

| したいこと | 操作 |
|---|---|
| 話しかける | 下の入力欄に打って Enter |
| 入力欄を出す/しまう | キャラを**クリック** |
| メニュー (モデル変更・描画モード・開発者ツール・しまう・終了) | キャラを**右クリック** |
| 移動する | キャラを**ドラッグ** |
| 吹き出しやメニューを閉じる | Esc |
| 開発者ツール (DevTools) を開く | **F12** または **Ctrl+Shift+I** (Mac は ⌘+Shift+I) |
| 描画モードを切り替える | **Ctrl+Shift+M** |
| 診断ログをもう一度出す | **Ctrl+Shift+D** |

キャラと UI 以外の場所はクリックが下のウィンドウに素通りするので、
デスクトップの上に置いたままふつうに作業できます。

### 中身

| ファイル | 役割 |
|---|---|
| `app/main.js` | ウィンドウ作成、クリック透過、LM Studio / VOICEVOX との通信、診断ログ |
| `app/preload.js` | 画面と Electron 本体をつなぐ窓口 |
| `app/renderer/stage.mjs` | three.js シーン、VRM 読み込み、基準姿勢、まばたき・呼吸、当たり判定 |
| `app/renderer/expression.mjs` | 表情をまぜる係 (感情のクロスフェード + 口 + まばたき) |
| `app/renderer/lipsync.mjs` | 口パク (音声の音量測定と、声が無いときの擬似口パク) |
| `app/renderer/talk.mjs` | 吹き出しと会話、声の再生、表情の切り替え |
| `app/renderer/main.mjs` | 透過の切り替え、ドラッグ移動、UI の取りまとめ |

ビルドツール (vite 等) は使っていません。素の HTML + ES modules と importmap だけです。
画面を出さずにできる範囲の自己点検は `npm run check` で走ります。

## 表情と口パク (Phase 3 / 4)

会話の内容に合わせて表情が変わり、しゃべっている間は口が動きます。
どちらも VRM の表情プリセットを使うので、**モデル側の準備は要りません**
(その表情を持っていないモデルなら、その感情だけ黙って飛ばします)。

### 感情の決め方 (3 段構え)

| 順番 | やり方 | いつ効くか |
|---|---|---|
| 1 (主軸) | **感情タグ**。返事の先頭に付いた `[happy]` を正規表現で剥がす | ふだんはこれ |
| 2 (保険) | **JSON (Structured Output)**。タグが無かった返事だけ、感情を聞き直す | タグを付け忘れたとき |
| 3 | **neutral** | どちらも取れなかったとき |

タグ方式を主軸にしたのは、**失敗したときの壊れ方が軽い**からです。
本文の生成そのものに JSON を強制すると、

- `json_schema` を知らないサーバーだと **400 が返って会話ごと止まる**
- 小型モデルは JSON に前置きやコードブロックを付けたがるので、**本文が読めなくなる**
- 「考えてから答える」モデルでは、思考と JSON の両立が実装によって怪しい

という壊れ方をします。タグ方式なら、外しても本文はそのまま読めて、感情が
neutral になるだけです。JSON 方式は**別便のリクエスト**にして、
本文の生成から切り離してあります (返事の表示は待たせず、判定できたら
あとから表情だけ差し替わります)。一度 400 が返ったサーバーには、
以後聞きに行きません。

### 使える感情タグ

| タグ | VRM 0.x での名前 | 一緒に受け付ける書き方 |
|---|---|---|
| `[neutral]` | neutral | normal / 普通 |
| `[happy]` | **joy** | smile / 嬉しい / 喜び |
| `[angry]` | angry | anger / 怒り |
| `[sad]` | **sorrow** | sadness / 悲しい |
| `[relaxed]` | **fun** | calm / 安心 |
| `[surprised]` | surprised | surprise / 驚き / びっくり |

- 全角の `【happy】`、括弧を忘れた `happy` だけの行、末尾に付けた `[sad]` も拾います
- **知らない単語のタグは剥がしません**。`(笑)` や `(ため息)` で始まる返事を
  食べてしまわないように、上の表に載っている語のときだけ切り落とします
- 剥がしたタグは**吹き出しにも VOICEVOX にも渡りません**。会話の履歴にだけ
  タグ付きのまま残します (タグを消した返事を履歴に積むと、モデルが
  「タグは要らないんだ」と学習して付けなくなるため)

### 感情タグの指示は `character.json` に書きません

タグを出してもらう指示は、送信のたびに**コード側で systemPrompt に足しています**
(`emotion.mjs` の `EMOTION_GUIDE`)。`character.json` に書き込む方式にすると、
人格を書き換えたときに一緒に消えて表情が動かなくなるためです。
自分で「感情タグ」の指示を書いた人のプロンプトは、そのまま尊重して足しません。

### 口パクのしくみ

声があるときと無いときで、口の駆動源が変わります。

```
声あり: wav → AudioBufferSourceNode → AnalyserNode → スピーカー
                                          ↓ 音量 (RMS)
                                        口の開き (aa)

声なし: 返事のテキスト → 1 文字ずつの譜面 → 口の開き (aa)
```

- **音素の判別はしません**。音量だけでも、しゃべっている感じは十分に出ます
- 音量をそのまま口に入れると機械的になるので、**開くのは速く・閉じるのはゆっくり**
  ならし、小さすぎる音は無音として口を閉じ、開き具合には上限を付けています
- VOICEVOX が起動していない環境では、**返事の文字数から擬似的に**口を動かします。
  句読点のところでは口を閉じて間を置きます。無言で棒立ちにはなりません

### 調整するところ

| 変えたいこと | ファイル | 定数 | 既定値 |
|---|---|---|---|
| 表情の切り替わりの速さ | `renderer/expression.mjs` | `EMOTION_FADE_SEC` | 0.25 秒 |
| 表情の濃さ | `renderer/expression.mjs` | `EMOTION_MAX` | 0.9 |
| 口の開きの上限 | `renderer/expression.mjs` | `MOUTH_MAX` | 0.85 |
| しゃべる時に表情をどれだけ譲るか | `renderer/expression.mjs` | `EMOTION_DUCK_BY_MOUTH` | 0.35 |
| 声が小さくて口が動かない | `renderer/lipsync.mjs` | `MOUTH_GAIN` を上げる | 4.5 |
| 無音でも口がひくつく | `renderer/lipsync.mjs` | `MOUTH_GATE` を上げる | 0.015 |
| 口の開閉の機敏さ | `renderer/lipsync.mjs` | `MOUTH_ATTACK_SEC` / `MOUTH_RELEASE_SEC` | 0.04 / 0.13 秒 |
| 擬似口パクの速さ | `renderer/lipsync.mjs` | `PSEUDO_CHAR_SEC` | 0.105 秒/文字 |

**表情と口がぶつかるとき**: `happy` のような表情は口の形も一緒に動かすので、
リップシンクの `aa` と重なると口がねじれることがあります。
口が開いているぶんだけ感情表情を薄めて (`EMOTION_DUCK_BY_MOUTH`) 譲らせています。
表情を優先したいなら 0 に、口の形をはっきり出したいなら大きくしてください。

なお**まばたきは感情と独立**に重なります (笑っていても瞬きします)。
表情への書き込みは `expression.mjs` の 1 か所にまとめてあるので、
感情・口・まばたきが互いの値を消し合うことはありません。

## 困ったときに (実機で出た不具合と、その直し方)

### 診断ログの見方

`npm start` した端末に `[診断]` で始まる行が出ます。困ったらこれをそのまま貼れば原因が追えます。

```
[診断] 起動: three 0.185.1 / @pixiv/three-vrm 3.5.5 / Electron 43.2.0 (Chrome 150) / win32 x64
[診断] VRM 読み込み: (モデル名) (VRM 1)
  メッシュ 13 個 / マテリアル 20 個 (MToon 20 / 標準 0 / うち輪郭線 7)
  テクスチャあり 20 個 / 半透明 0 個 / 表情 18 種 / 姿勢に使う骨 6/6
  描画モード: 通常 (MToon)
  表情: 使える感情 6/6 (neutral, happy, angry, sad, relaxed, surprised)
    口 (リップシンク)=aa / まばたき=blink
    いまの重み: neutral=0 happy=0.9 angry=0 ... / 口=0.196 / まばたき=0 (目標=happy)
    - Body_00_SKIN [ShaderMaterial/MToon] テクスチャ=srgb 半透明=false ...
  口パク: 駆動源=実音声 (AnalyserNode) 開き=0.196
[診断] LLM: model=... finish_reason=stop content=0文字 reasoning=412文字 本文の取り出し元=reasoning
[診断] 感情: happy (取得方式=タグ)
[診断] 口パク: 駆動源=実音声 (AnalyserNode) — 音声 48044 バイトを解析して口を動かします
```

見るところ:

- **テクスチャあり が 0** … 画像が 1 枚も読めていない。キャラは真っ白になります (下の 1. 参照)
- **マテリアル 0 個** … VRM への変換に失敗している。ファイルが壊れていないか確認
- **姿勢に使う骨 が 6 未満** … 肩や肘のボーンが無いモデル。腕の下ろし方が甘くなります
- **LLM の行** … 返事が空のときはここを見る (下の 4. 参照)
- **使える感情 が 6 未満** … そのモデルに無い表情。足りない感情は neutral のままになります
- **感情の行** … 取得方式が `タグ` / `JSON/Structured Output・後追い` / `なし` のどれか。
  いつも `なし` ならモデルがタグを付けてくれていません (短く話しかけるか、
  `character.json` の systemPrompt に「短く答える」と書くと落ち着くことがあります)
- **口パクの行** … 駆動源が `実音声 (AnalyserNode)` なら声に追従、
  `擬似 (テキスト長)` なら VOICEVOX が起動していない (または音を解析できなかった) 状態

画面側 (ブラウザ) のエラーは **F12 / Ctrl+Shift+I** で開く DevTools の Console に出ます。
警告以上は端末にも `[診断] 画面側:` として転送されます。

### 1. キャラが輪郭線だけで、面が真っ白になる (修正済み)

**原因**: `index.html` の Content-Security-Policy の `connect-src` に `blob:` が無かったこと。

`.vrm` (中身は `.glb`) に埋め込まれたテクスチャは、three.js の GLTFLoader が
いったん Blob に変換し、`blob:` URL 経由で読み込みます。今の three は `<img>` ではなく
**ImageBitmapLoader (中身は `fetch`)** を使うため、`img-src` ではなく **`connect-src` の許可**が要ります。
ここが `'self'` だけだと全テクスチャの読み込みが CSP に止められ、
マテリアルが「色だけ = 白」の状態で描かれます。
輪郭線は別の色 (`outlineColorFactor`) なので残り、**輪郭だけ見えて中身が真っ白**になります。

`connect-src 'self' blob: data:` に直しました。外部ホストは相変わらず一切許可していません。
再発防止に `npm run check` でも見張っています。

### 2. キャラ全体が白く飛んで、陰影が見えない (修正済み)

**原因**: ライトが明るすぎたこと。

three r155 以降、ライトの強さは物理単位です。MToon のシェーダーは受け取った光を
1/π 倍してからテクスチャ色に掛けるので、**光の合計 intensity が π を超えた分は白飛び**します。
MToon はトーンマッピングを通らないため、超えた分はそのまま切り捨てられます。
以前は `π + π×0.45 = 約1.45倍` で、キャラの画素の 67% がどこかの色を振り切っていました。

キーライト `π×0.7` + 環境光 `π×0.32` (合計が π をわずかに下回る) に直し、
振り切る画素を 67% → 7% まで下げました。

### 3. T ポーズのまま立っている (修正済み)

読み込み直後に、VRM の正規化ボーン (`leftUpperArm` / `leftLowerArm` / 肩) へ
自然な立ち姿を当てるようにしました。VRM 0.x / 1.0 のどちらでも同じ名前で引けるので、
版の違いは意識しなくて構いません。肩や肘が無いモデルは、その骨だけ飛ばします。

この姿勢は**基準姿勢**として保持し、呼吸・まばたきは**そこからの差分**として足しています
(直接値を入れていた頃は、アイドルが基準姿勢を上書きして T ポーズに戻っていました)。

### 4. 話しかけると吹き出しが空っぽになる (修正済み)

**原因**: **Gemma 4 のような「考えてから答える」(reasoning) モデル**への対応漏れ。

LM Studio の画面に「Thought for 7.09 seconds」と出るモデルは、
OpenAI 互換のレスポンスで本文の置き場所が一定しません。

| パターン | 中身 | 直し方 |
|---|---|---|
| A | `content` に `<think>…</think>本文` が入る | 思考タグを剥がして本文だけ出す |
| B | `content` が**空文字**で、思考が `reasoning_content` に入る | `content` が空なら `reasoning_content` を見る |
| C | 思考だけで `max_tokens` に達し、本文が出ないまま終わる | 枠を広げる + 空なら理由を吹き出しに出す |

以前は `content` を素直に読むだけだったので、B と C で**無言の空返事**になっていました。

直したこと:

- `<think>` `<thinking>` `<reasoning>` などの思考タグを除去して本文を取り出す
  (開きタグだけ / 閉じタグだけ、という壊れた出力にも対応)
- `content` が空なら `reasoning_content` / `reasoning` / `thinking` を順に見る
- `max_tokens` を **300 → 1024** に引き上げ。考えるモデルと分かったら **2048**
  (モデル名から推測 + 一度でも思考を返したら記憶する)
- `finish_reason` が `length` なら「途中で切れています」と吹き出しに添える
- それでも本文が取れなければ、**黙って空にせず**「考えるだけで終わってしまいました」と案内を出す
- 同じ処理を `chat.mjs` (ターミナル版) にも入れて、挙動を揃えた
  (`COMPANION_DEBUG=1 node chat.mjs` で内訳が見えます)

**考えるモデルを使うときの注意**: 思考ぶんもトークンを食うので、返事が遅くなります。
短く返してほしいときは `character.json` の `systemPrompt` に「短く答える」と書くのが効きます。
LM Studio 側で thinking を切れるモデルなら、切ったほうが軽快です。

### それでも直らないとき: 描画モードの切り替え

MToon で映らない事情が残っている場合の逃げ道として、
**MToon を three 標準の `MeshStandardMaterial` に置き換えて描くモード**を用意しました。

- 右クリックメニューの **「描画モードを切り替える」** か **Ctrl+Shift+M**
- トゥーンの陰影と輪郭線は失われますが、まず「映る」ことを確かめられます
- 選んだモードは記憶され、次回の起動にも引き継がれます

これで映るなら MToon 側の問題、これでも映らないならモデルか WebGL 側の問題、と切り分けられます。

## キャラを変える

`character.json` を書き換えるだけ (`chat.mjs` と `app/` の両方が同じファイルを読みます)。

- `name` … 表示名
- `systemPrompt` … 人格・口調・一人称など。ここが人格の半分
- `voicevoxSpeaker` … VOICEVOX の話者番号 (3 = ずんだもん ノーマル)。
  番号一覧は VOICEVOX 起動中に http://localhost:50021/speakers で見られる

## 設計メモ

- 脳への接続は OpenAI 互換 API (`localhost:1234/v1/chat/completions`)。
  クラウド (Claude API 等) に切り替えるときは、送り先の URL とキーを変えるだけ
- 会話履歴は直近 20 往復だけ保持。長期記憶は Phase 6 で SQLite に置く予定
- キャラクター (VRM モデル) は同梱しない方針。「あなたの推しを入れる器」にする

### Phase 2 で決めたこと

- **クリック透過**は 2 段構え。
  `setIgnoreMouseEvents(true, { forward: true })` で下のウィンドウへ素通りさせつつ、
  マウスの移動だけは受け取る。その座標を毎フレーム見て、
  ①UI 部品の上か (`elementFromPoint`) ②キャラの上か (画面上の矩形でふるい分け → レイキャスト)
  を判定し、当たっていれば透過を解除する。
  ピクセルの透明度を読む方式より軽く、髪の隙間などキャラの形どおりに抜ける。
  当たらなくなってから 150ms の猶予を置いているのは、輪郭で判定が高速に
  入れ替わってクリックを取りこぼすのを防ぐため
- **ウィンドウ移動**に CSS の `-webkit-app-region: drag` は使わない。
  あれは矩形単位でしか指定できず「キャラの形だけ掴む」ができないため、
  掴んだ瞬間のカーソル位置を覚えて main 側で追従させている
- **キャラの向き**は左右の上腕の位置から計算する。
  VRM 0.x / 1.0 で正面の基準が違うが、この方法なら必ず顔がこちらを向く
- **通信は main プロセスが代行**する。画面側から直接 LM Studio を叩くと
  CORS で弾かれるため。VOICEVOX の音声も main が取ってきて画面側で鳴らす
- ビルドツールは入れない。importmap で `node_modules` を直接 import している

### Phase 2 の実機テストで分かったこと

- **CSP は `img-src` だけ見ていると足をすくわれる**。three.js は画像を
  `fetch` で読むので `connect-src` の管轄。詳しくは「困ったときに」の 1.
- **MToon は物理ベースではない**ので、three の「intensity は π 倍が基準」を
  そのまま足し込むと白飛びする。光の合計は π を超えさせない
- **アイドルモーションは基準姿勢からの差分で書く**。値を直接入れると、
  あとから姿勢を足したときに上書きされる
- **診断ログは端末に出す**。画面側の `console.log` は DevTools を開かないと
  見えないので、困ったときに貼ってもらえない。main プロセス経由で標準出力に流す
- **ローカル LLM は「返事が空」を前提に書く**。考えるモデルは本文の置き場所が
  一定しないので、素直に `content` だけ読むと無言になる

### Phase 3 / 4 で決めたこと

- **小型モデルに構造を求めるときは、失敗の壊れ方で選ぶ**。JSON を強制すると
  本文ごと読めなくなる失敗をするが、タグ方式は「感情が neutral になるだけ」で済む。
  正しく動く確率より、外したときの被害の小ささを採った
- **付け足しの情報は、本文の生成と同じ便に乗せない**。感情の JSON 判定は
  別リクエストにして、返事の表示を待たせない。判定できたら表情だけ後から変える
- **表情への書き込みは 1 か所に集める**。`expressionManager.setValue` は
  毎フレーム全部を入れ直す作りなので、感情・口・まばたきを別々の場所から書くと
  最後に書いた人が勝ってしまう。`expression.mjs` で足し合わせてから 1 回だけ入れる
- **ブラウザに触らない計算は切り出す**。音量→口の開き、擬似口パクの譜面、
  クロスフェードは純粋な関数にしてあるので、GUI の無い環境でも
  `npm run check` が数値で検証できる
- **VRM 0.x の旧名は表で吸収する**。joy / sorrow / fun のように、
  1.0 と名前が違う表情がある。候補を順に当たって、実在するほうを使う
